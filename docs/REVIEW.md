# 독립 검토 — 중간 구현

검토일: 2026-11-02. 검토 범위는 Java/XML 소스, Room 저장/잠금, 센서 수명주기, 카메라 비동기 처리, AR/GPS 경로, 기존 검증 산출물이다. 검토자는 에뮬레이터 입력을 수행하지 않았으며, 실행 조작과 최종 사용자 경로 확인은 총괄이 담당한다.

## 판정

중간 범위의 주요 구조는 충족한다. 사진·조도·음성/입력의 첫 3개 미션에 발견 → 이야기 → 행동 → 시설 질문 → 저장 → 보상 경로가 존재한다. 4번 방향은 현장 정보가 없어 명시적 대체 조작이며, 5번은 가속도와 대체 조작이다. 실제 AR/GPS/센서의 현장 작동 완료를 뜻하지 않는다.

최종 통과 조건은 아래 수정의 소스 확인, 최신 소스의 품질 게이트 통과, 총괄의 연속 3개 미션 실행·재시작 저장 검증이다. 발견된 사항은 구현 PM 또는 총괄에게 전달했다.

## 확인한 안전장치

- Room 기본 키 `(mode, missionId)`가 테스트/현장 기록을 구분하고, 트랜잭션 안에서 선행 미션을 확인한다. 중복 삽입을 무시하여 같은 미션의 보상이 누적되지 않는다.
- 현장 검증 전 후보 좌표는 JSON에서 `false/null`이며, 홈과 미션 진입 모두 현장 실행을 막는다. 좌표를 만들어 넣지 않았다.
- ARCore Session, 평면 hit-test, Anchor, 월드 좌표 렌더링·선택 경로가 존재하고, 일반 카드는 결과를 `CARD`로 분리한다. 단순 카메라 오버레이를 AR 완료로 저장하지 않는다.
- 위치는 전경 업데이트만 받고 마지막 저장 위치를 도착 증거로 사용하지 않는다. 정확도·최신성·반경·체류 판정이 별도 순수 클래스에 있다.
- 조도는 on-change 센서가 조용해도 타이머로 연속 조건을 평가하며, 너무 어두운 환경/센서 부재에는 대체 조작이 있다. 길게 누르기는 떼기·취소·버튼 밖 이동·화면 중지 때 취소된다.
- 가속도는 중력 크기 차이, 임계값 복귀, 시간 간격을 사용하여 한 번의 움직임을 매 프레임 중복 계산하지 않는다.
- 미션/AR Activity는 외부 노출되지 않는다. 초기화 사진 삭제는 앱 파일 디렉터리의 정규 경로 내부만 허용한다.
- 완료 화면은 저장 콜백 성공 후 표시되며, 실패 시 재시도 경로가 있다.

## 수정 요청과 상태

1. **수정 확인 — 카메라 지연 콜백과 중복 촬영.** `capturePending`, 비활성 촬영 버튼, 세대 번호와 Activity 종료 검사, 종료 시 바인딩 해제가 추가되었다. 종료 후 도착한 사진은 삭제한다. 소스에서 확인했으며 카메라 실행 검증은 총괄 기록을 따른다.
2. **수정 확인 — 임시 사진 누적.** 재촬영·미션 취소 시 미저장 사진 삭제가 추가되었다. 저장 중 Activity 종료는 DB 콜백까지 삭제를 보류하여 저장된 사진이 지워지지 않게 한다. 완료된 미션은 도감으로 이동한다.
3. **수정 확인 — 초기화 후 오래된 화면.** 성공 여부와 관계없이 기록을 재조회하며 정리 실패를 안내한다.
4. **수정 확인 — 로컬 저장 안내와 백업 설정.** `allowBackup=false`와 기존/최신 백업 규칙의 앱 파일·DB·설정 제외를 확인했다. 최신 규칙은 기기 간 전송도 제외한다.
5. **수정 확인 — GPS 연속성.** 5초가 넘는 수신 공백이나 역행 시 체류가 초기화되도록 총괄이 보완했다. 현재 모든 현장 좌표가 차단되어 실제 현장 실행은 여전히 별도 검증 대상이다.
6. **수정 확인 — 새 코스 안내도 XML 내부 클래스 이름.** `RouteMapActivity.RouteView`라는 잘못된 참조를 Lint `InnerclassSeparator` 경고로 발견하여 전달했다. 총괄이 `view` 요소의 `class="com.example.firststep.RouteMapActivity$RouteView"` 형태로 고친 소스를 확인했다. 수정 후 실제 화면 열기 결과는 총괄 검증에 남긴다.
7. **AR 화면 수명주기 보완 제안.** 자동 AR 서비스 설치를 피하기 위한 명시적 `AR로 찾기` 진입과 카드 대체 경로를 확인했다. AR을 시작하지 않은 경우에도 `GLSurfaceView.setRenderer`가 만든 스레드를 화면 중지 시 정지하도록 `surface.onPause()`를 `active` 조건 밖으로 옮기는 소규모 자원 정리를 총괄에게 제안했다.

## 증거와 검증 한계

- JUnit XML 산출물: 2026-11-02 19:02:42 KST, 6개 모음의 15개 테스트, 실패/오류 0. 진행 선행 조건, 발견/완료 방식, 조도 시간 조건, 위치 경계·수신 공백, 입력·길게 누르기 순수 판정을 다룬다. 동일 시점 APK 생성, Lint는 오류 0/경고 44다. 그중 안내도 내부 클래스 경고는 실제 실행 오류로 이어지는 사항이므로 위 수정 요청에 별도 기록했다. 이후 최종 결과는 총괄의 `docs/VERIFICATION.md`를 기준으로 한다.
- 에뮬레이터 로그 읽기: 최초 홈 버튼 문제를 확인한 시점에 FirstStep `FATAL EXCEPTION`이나 `MissionActivity START` 기록이 없었다. 총괄이 홈 재진입 후 정상 진입을 확인했으므로 재현 가능한 충돌로 판정하지 않는다.
- 현재 단위 테스트는 실제 Room 장치 DB의 마이그레이션·저장 재시작을 실행하지 않는다. 에뮬레이터 재시작 후 기록 조회가 별도 필수다.
- 실제 기기의 카메라, 한국어 TTS/음성 인식 제공자, 조도/가속도, AR 추적, GPS 도착은 별도 기기·현장 검증 대상이다. 센서 대체 조작 통과는 센서 자체 검증이 아니다.
- 방향 미션의 실제 방위 판정과 검증된 실제 시설 좌표·시설 세부 정보는 중간 범위에서 미완료로 명시해야 한다.
