# 첫발자국 제안·중간발표 통합 피드백

- 정리일: 2026년 11월 5일
- 대상: 제안발표 피드백, 중간발표 교수님 피드백, 팀원을 통해 추가 전달된 의견
- 목적: 발표 단계별 피드백을 모아 프로젝트 목적, 건물 정보 조사, 미션·스토리 설계, 구현 및 발표 개선 기준으로 활용한다.

> 피드백은 사용자 전달 내용과 기존 기획서의 피드백 정리를 바탕으로 요약했다. 녹취 직접 인용이 아니다. 추가 전달 내용은 교수님 발언과 팀원 해석의 경계가 명확하지 않아 특정인의 발언으로 단정하지 않는다. 개선안·예시는 검토 제안이며 확정 기획이나 구현 완료를 뜻하지 않는다.

## 1. 전체 피드백의 핵심

**신입생이 건물에 익숙해지는 것이 목적이다. 먼저 각 건물의 역할과 실제 이용 정보를 조사하고, 그 정보를 직접 확인하게 하는 미션을 만든 뒤, 미션에 자연스럽게 맞는 스마트폰 기능을 선택해야 한다. 이야기·체험·퀴즈·다음 건물 이동이 하나의 흐름으로 연결돼야 한다.**

기술 활용 방향은 긍정적으로 평가받았지만, 어떤 장소에서 어떤 행동을 하고 무엇을 배우는지에 대한 구체성이 부족하다는 지적이 반복됐다. 발표자료도 이 경험이 보이도록 정보량을 줄일 필요가 있다.

## 5. 프로젝트 목적과 설계 순서

### 목적

신입생이 주요 건물의 위치뿐 아니라 **무엇을 하는 건물인지, 어떤 시설이 있는지, 어떤 상황에서 이용하는지**를 직접 확인하고 기억하도록 돕는다.

### 앞으로의 설계 순서

1. 탐방할 건물과 접근 가능한 구역을 정한다.
2. 공식 안내와 현장 조사를 통해 건물 정보를 확인한다.
3. 건물별로 사용자가 알아갈 핵심 정보 1~2개를 정한다.
4. 그 정보를 직접 관찰하거나 이용 상황을 판단하는 체험을 만든다.
5. 체험에 필요한 스마트폰 기능과 선택 근거를 정한다.
6. 이야기, 미션 조건, 실패·대체 흐름, 퀴즈, 저장 항목을 정한다.
7. 대표 건물 하나에서 실제 기기 검증을 한 뒤 다른 건물로 확장한다.

## 6. 건물별 사전 조사 항목

| 조사 항목 | 확인 내용 |
| --- | --- |
| 기본 정보 | 공식 건물명, 위치, 주요 출입구, 주변 건물 |
| 건물의 역할 | 수업·학습·행정·학생 편의 등 주요 용도 |
| 내부 구성 | 주요 시설과 층별 위치, 사용하는 학과·부서 |
| 이용 상황 | 학생이 어떤 일을 하러 방문하는지, 이용 절차와 제한 |
| 관찰 단서 | 건물명 표식, 층별 안내도, 공개 안내판 등 |
| 현장 조건 | 출입·촬영 가능 여부, 운영 시간, 소음, 조명, 이동 경로 |
| 정보 근거 | 공식 안내 출처, 현장 확인일, 변경 여부 |
| 학습 목표 | 미션 후 사용자가 설명할 수 있어야 하는 내용 |

모든 층과 학과 정보를 퀴즈로 만들 필요는 없다. 조사한 내용 중 신입생에게 유용하고 현장에서 확인 가능한 정보만 선정한다. 확인하지 않은 시설·층·학과 배치는 사실처럼 작성하지 않는다.

## 7. 건물별 체험과 전체 스토리 흐름 제안

기존 ‘다섯 개의 기억 찾기’ 설정을 유지한다면, 각 기억을 건물의 역할과 연결하는 방식으로 구체화할 수 있다. 예를 들어 ‘첫 수업 준비’, ‘학습 공간 찾기’, ‘학생 지원 이용’처럼 실제 대학생활의 필요가 다음 장소로 이어지도록 한다. 이는 이야기 검토안이며 실제 장소와 에피소드는 미확정이다.

### 건물 한 곳의 기본 흐름

**방문 안내 → 도착 확인 → 짧은 이야기·목표 제시 → 현장 정보 관찰 → 스마트폰 상호작용 미션 → 현재 건물 복습 퀴즈 → 기록 저장 → 다음 건물 단서·객관식 선택 → 다음 장소 안내**

- 방문 안내: 왜 이 건물을 찾아가는지 알려준다.
- 현장 관찰: 표식이나 안내도를 통해 정보를 직접 확인한다.
- 체험: 관찰한 내용을 활용하는 행동을 수행한다.
- 복습 퀴즈: 현재 건물의 역할이나 시설 정보를 다시 확인한다.
- 다음 건물 선택: 다음 생활 상황에 필요한 장소를 고른다.
- 오답 처리: 짧은 해설과 재시도를 제공한다.
- 마지막 건물: 다음 장소 선택 대신 전체 탐방 정리와 도감 확인으로 마무리한다.

### 퀴즈의 두 역할

| 구분 | 질문 형태 예시 | 목적 |
| --- | --- | --- |
| 현재 건물 복습 | ‘방금 확인한 이 시설에서는 어떤 일을 할 수 있나요?’ | 지금 방문한 건물의 역할을 기억한다. |
| 다음 건물 예고 | ‘다음에는 책을 빌리려고 합니다. 어느 건물로 가야 할까요?’ | 다음 장소와 이용 목적을 연결한다. |

다음 건물 이름만 맞히게 하면 현재 건물 복습이 충분하지 않을 수 있다. 두 역할을 구분하되 문항 수를 과도하게 늘리지 않는다. 아직 알려주지 않은 정보는 단서를 제공하고, 실제 이동 위치는 정답 후 지도·안내로 보여준다.

## 8. 미션과 스마트폰 기능 연결 기준

| 기능 | 적합한 역할 | 반드시 검토할 점 |
| --- | --- | --- |
| GPS | 건물 주변 도착 확인 | 실측 좌표와 오차 반경. 실내 층 판정 수단으로 취급하지 않는다. |
| 카메라 | 표식·안내판 관찰과 탐방 사진 기록 | 촬영 허용과 주변 사람 노출. 사진 확인과 자동 건물 인식은 구분한다. |
| 음성 | 시설명 답변이나 짧은 상호작용 | 말할 이유와 장소의 소음·정숙 조건. 텍스트 대체 제공 여부 |
| 조도 센서 | 실제 밝기 관찰이 의미 있는 체험 | 밝기를 측정해야 시설 이해에 도움이 되는지. 임의로 센서를 가리는 조작은 재검토한다. |
| 자이로스코프 | 기기의 회전·자세 변화를 이용하는 조작 | 기기를 돌리는 행동의 학습상 이유. 절대 방위나 층을 직접 알아내는 기능으로 설명하지 않는다. |
| 방향 관련 센서 | 주변 건물이나 목적지 방향 확인 | 자이로와 구분하고 기기 지원·자기장 간섭을 검증한다. |
| 가속도 센서 | 움직임 변화가 필요한 체험 | 흔들기 자체가 목적이 되지 않도록 하고 보행 중 위험한 조작을 피한다. |
| AR | 장소 단서·이야기 발견 | 공간 인식 실패 대응. 오브젝트 선택 뒤 실제 시설 정보로 연결한다. |

사진·음성·위치는 센서와 동일한 분류는 아니지만, 사용자 체험에 쓰는 스마트폰 기능으로 함께 정리한다. 모든 건물에 모든 기능을 넣는 것은 확정 요구가 아니다.

## 9. 대표 미션 명세 예시

### 수업 건물: ‘내 첫 수업 장소 확인하기’ — 검토안

- 목적: 건물의 이름과 주요 공간을 익힌다.
- 사전 조사: 공식 건물명, 공개 안내도, 주요 시설·학과와 층 정보, 촬영 가능 구역.
- 이야기: 첫 수업을 준비하며 건물과 필요한 공간을 찾는 상황을 제시한다.
- 행동: 건물명 표식을 찾고 촬영한 뒤, 안내도를 보고 지정된 공개 시설의 위치를 확인한다.
- 기능과 근거: 카메라를 통해 표식을 직접 관찰하고 개인 탐방 기록을 남긴다.
- 완료 조건 초안: 사진 확인과 안내도 기반 객관식 정답을 모두 충족한다. 실제 건물 자동 인증 여부는 별도 구현 범위로 정한다.
- 복습: 방금 확인한 건물의 역할 또는 주요 시설을 묻는다.
- 다음 장소: 다음 생활 상황에 필요한 건물을 객관식으로 선택한다.
- 저장: 완료 여부, 선택한 답, 사진 경로 등 필요한 항목을 정한다.
- 대체·실패: 촬영 권한 거부, 표식 가림, 출입 제한 시 안내와 대체 흐름을 정한다.
- 미확정: 실제 건물, 시설명, 층, 학과, 정답과 좌표는 조사 후 입력한다.

## 10. 구현 전 확정할 미션 명세

각 건물에 대해 다음 양식을 한 장씩 작성한다.

| 항목 | 작성 내용 |
| --- | --- |
| 장소·학습 목표 | 어디서 무엇을 알게 할 것인가? |
| 정보 근거 | 공식 출처와 현장 확인 결과는 무엇인가? |
| 이야기 | 이전 건물에서 왜 이곳으로 왔는가? |
| 관찰·행동 | 무엇을 보고 어떤 조작을 하는가? |
| 기능·근거 | 어떤 스마트폰 기능을 왜 쓰는가? |
| 성공 판정 | 어떤 입력과 조건으로 완료되는가? |
| 퀴즈·해설 | 무엇을 묻고 오답에 어떻게 설명하는가? |
| 다음 장소 | 어떤 단서로 다음 건물을 고르게 하는가? |
| 실패·대체 | 권한 거부·미지원·인식 실패 시 어떻게 하는가? |
| 저장·복원 | 무엇을 저장하고 중단 후 어디서 재개하는가? |
| 검증 상태 | 기획, 구현, 에뮬레이터 검증, 실기기·현장 검증 중 어디까지 했는가? |

## 11. 실행 우선순위

| 순서 | 작업 | 산출물·완료 기준 |
| --- | --- | --- |
| 1 | 탐방 건물 선정과 정보 조사 | 실제 건물별 정보표, 출처, 접근 조건 |
| 2 | 건물별 학습 목표와 전체 이야기 확정 | 다섯 건물이 이어지는 이유와 배울 내용 |
| 3 | 대표 건물 미션 상세 설계 | 관찰·기능·판정·퀴즈·대체 흐름 명세 |
| 4 | 대표 미션 현장 검증 | 실제 장소와 기기에서 수행 가능함을 확인 |
| 5 | 나머지 건물로 확장 | 건물마다 목적에 맞는 체험과 연결 퀴즈 |
| 6 | 저장·해금·복원 통합 점검 | 중단·오답·재시도 상황에서도 흐름 유지 |
| 7 | 최종 발표자료 재구성 | 실제 화면으로 목적과 대표 체험을 설명 |

기존 구현은 위 설계와 비교해 유지·수정·제외를 결정한다. 모든 기능을 새로 개발하거나 현재 구현을 완료한 것으로 전제하지 않는다.

## 12. 발표자료 개선 기준

- 첫 장에서 ‘누가, 어디에서, 무엇을 배우는 앱인지’를 설명한다.
- 한 슬라이드에 핵심 메시지 하나를 둔다.
- 대표 미션을 실제 화면 3~4개로 보여주고 짧은 설명을 붙인다.
- ‘기술 이름 → 기능 목록’보다 ‘건물 정보 → 사용자 행동 → 기술 선택 이유 → 결과’ 순으로 설명한다.
- 테스트 수치와 상세 구조는 보조 자료로 옮긴다.
- 구현과 검증 상태를 구분하고 남은 현장 과제를 제시한다.

## 13. 미확정 사항

- 최종 탐방 건물과 순서
- 각 건물의 실제 시설·층·이용 학과와 정보 출처
- 건물별 체험과 센서·상호작용 기능 배정
- 스토리 대사와 건물 간 이동 이유
- 현재 건물 복습 및 다음 건물 선택 문항
- 완료 판정값과 대체 흐름
- 기존 구현 중 유지·수정·제외할 부분
