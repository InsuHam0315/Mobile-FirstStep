# 개발 하네스

## 지휘 및 소유권

- 총괄: 현재 Astra 채팅. 요구 범위, 실제/테스트 데이터 구분, AR/GPS 통합, 최종 검증.
- 구현 PM: GPT-6.1 Sol. 작업 분해, 파일 소유권 배정, 인터페이스 계약, 빌드 오류 해결.
- 독립 검증 PM: GPT-6.1 Sol. 구현 담당과 분리하여 소스/검증 산출물 검토, 오류 재현 조건 및 수정 확인.
- UI/장치 구현: GPT-6.1 Terra. Java/XML 화면, CameraX, 음성, 미션 흐름.
- 데이터/판정 구현: GPT-6 Luna. JSON, Room, 진행 규칙, 단위 검증. 현재 런타임은 6.1 Luna를 제공하지 않으므로 사용 가능한 Luna 모델을 사용.

서로 같은 파일을 병렬 수정하지 않는다. 의존 기능은 Java 메서드/Activity 결과 계약을 먼저 합의한다. 각 담당은 변경·검증·제약을 PM에게 전달하고 총괄이 통합 결과를 확인한다. 작업 중 모델 이름을 구현 기능이나 앱 화면에 표시하지 않는다.

## 개발 범위와 우선순위

교수 피드백 반영 기획서를 기준으로 Java/XML 네이티브, 5개 후보 장소, 한 편의 순차 탐방을 유지한다. 제안 PDF의 6개소/10개 미션 수치는 최신 기획과 다르므로 구현 기준으로 혼합하지 않는다. 중간 범위는 주요 화면, 최소 3개 미션의 시작-발견-행동-질문-보상-저장 연결이다. 발표 자료 제작은 제외한다.

현장 검증 전 좌표를 지어내지 않는다. 테스트 코스와 현장 기록을 분리하고, 카드 발견은 AR 완료로 표시하지 않는다. 실제 AR은 ARCore 추적/평면 hit-test/앵커 기반 오브젝트 선택 경로다.

## 인터페이스

- `ArDiscoveryActivity`: 결과 `RESULT_OK`, `discoveryMethod=AR|CARD`. 중단 시 완료하지 않는다.
- `LocationController`: 전경 위치 수신만 사용, 마지막 저장 위치로 도착을 인정하지 않음. 화면 중지 시 `stop()`.
- `ArrivalPolicy`: 정확도 25m 이내, 10초 이내 위치, 40m 진입 3초 체류, 60m 이탈. 부정확하거나 오래된 측정 시 도착 취소.
- 기록: 모드별 별도 저장, 선행 미션 확인, 중복 보상 금지. 완료 저장 실패 시 성공 표시 금지.

## 품질 게이트

1. 소유권·계약 확인 후 구현.
2. 순수 판정 로직 단위 검증: 상태 전환, 잘못된 입력, 시간 경계, 중복 처리.
3. `scripts/verify.ps1`: 단위 테스트, 디버그 APK, Android Lint. 실패 시 수정 후 해당 게이트 재실행.
4. 에뮬레이터: 최초 시작, 테스트 코스, 잠금/해금, 카드 대체, 입력/질문, 저장 후 재실행, 도감, 초기화.
5. 실제 기기/현장: 센서, 카메라, AR 추적, GPS와 좌표. 에뮬레이터 결과를 실제 기기 검증으로 보고하지 않음.

검증 결과와 남은 한계는 `docs/VERIFICATION.md`에서 관리한다.
