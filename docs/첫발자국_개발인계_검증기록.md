## 3. 기능별 판정 계약

### GPS

40m 진입 / 60m 이탈, 정확도 25m 이하, 위치 경과 10초 이내, 3초 체류. 측정 사이 5초 초과 공백은 연속 체류로 보지 않는다. 마지막 저장 위치로 도착을 인정하지 않는다. 현장 미션을 복원하거나 전경으로 돌아오면 도착을 다시 확인한다.

### 방향

회전벡터 우선, 미지원 시 가속도+지자기. 화면 회전 방향으로 축을 재배치한다. fallback 센서 쌍의 오래된 값을 재사용하지 않는다. 목표 오차 ±12도, 1.5초 연속 유지, 중간 이상의 정확도, 500ms 초과 측정 공백 시 유지 초기화.

- DEMO: 실제 센서로 자북 0도 맞추기. 학교 목적지 방위라고 표시하지 않는다.
- FIELD: 최신 유효 위치와 다음 순서의 검증된 장소 좌표로 방위 계산, `GeomagneticField` 편각으로 진북 기준 통일.
- 미지원/불안정/목표 좌표 미확인: 명시적인 HOLD 대체 경로. 실제 센서 성공과 구분해 저장.

### 사진·빛·움직임·음성

- PHOTO: CameraX 촬영 파일 존재 → 미리보기 확인 → 시설 질문. 자동 건물 식별을 하지 않는다.
- LIGHT: 1.5초 기준 밝기, 기준의 35% 이하 0.8초, 75% 이상 회복 0.8초. 어두운 환경/부재에는 대체 조작.
- ACCELEROMETER: 저역통과 중력 벡터 제거, 초기 안정화, 약 3m/s² 이상의 별도 움직임 5회. 임계값 복귀와 500ms 간격 적용.
- HOLD: 버튼을 3초 연속 누름. 떼기/밖 이동/취소/화면 중지 시 취소.
- SPEECH/TYPED: 안내 후 허용 정답을 정규화해 비교. 시스템 음성 서비스의 처리·네트워크 사용을 안내. TTS 한국어 지원을 확인한다.

### 저장 및 복원

Room 기본키는 `(mode, missionId)`. 보상 표시 전 저장 성공을 확인하고, 선행 미션/미션별 완료 방식을 검사한다. 발견 방식 `AR/CARD`와 조작 방식 `PHOTO/LIGHT/HOLD/SPEECH/TYPED/COMPASS/ACCELEROMETER`를 별도로 저장한다. `LEGACY`는 이전 DB 기록의 메타데이터다.

체크포인트 단계는 `DISCOVERY/STORY/GAME/PHOTO_PREVIEW/QUIZ/SAVING/SUCCESS`. 사진 미리보기와 텍스트 입력은 복원하고 센서 측정은 처음부터 다시 한다. SAVING/SUCCESS 복원은 실제 DB 완료 여부와 사진 소유권을 먼저 확인한다. 오래된 Activity가 새 Activity의 초안이나 Room 소유 사진을 지우지 않게 한다.

## 4. 지도 데이터의 출처와 제한

- 기본 지도는 OpenStreetMap 표준 타일을 네이티브 Canvas에 표시한다. 웹 화면을 감싼 앱이 아니다.
- 학교 전체 보기 중심: `35.9456011, 126.6802365`. OSM/Nominatim의 군산대학교 대학 영역 중심 메타데이터이며, 현장 측정 좌표나 미션 도착점이 아니다.
- 출처 객체: `https://www.openstreetmap.org/way/345733566`.
- 현재 화면의 타일만 요청, 앱 식별 User-Agent, 출처 표시, HTTP 캐시/조건부 요청. 미리 다운로드/전체 지역 스캔/오프라인 다운로드 기능 없음.
- 인터넷이 없으면 이미 본 지도 캐시를 정책이 허용하는 범위에서 사용하거나 재시도 안내를 표시한다. 코스/도감/저장은 로컬로 동작한다.
- 최신 위치의 오차 범위를 표시하지만 위치 표시 자체가 도착 인증은 아니다. 확인된 미션만 숫자 지점으로 표시한다. 경로 자동 탐색은 구현하지 않았다.
- OSM 정책: https://operations.osmfoundation.org/policies/tiles/ / 저작권: https://www.openstreetmap.org/copyright

## 5. 검증 근거

최종 결과: 단위 검사 **34개**, 기기 검사 **4개** 통과, APK 빌드 성공. Lint **오류 0개·경고 78개**. 경고는 남아 있으므로 정적 검사 전체가 무경고인 것은 아니다. FIELD 방향 미션 시작 시 위치 최신성을 다시 확인하는 마지막 변경 후 단위 검사·빌드·Lint를 재통과했다.

마지막 APK에 전체 5미션 테스트를 직접 다시 실행해 **1개 통과(25.636초)**를 확인했다. 이는 4개 기기 검사 중 통합 시나리오를 반복한 결과이며, 별도의 다섯 번째 테스트로 합산하지 않는다. 이후 프로세스 강제 종료/재실행에서 `5 / 5 완료`, 실제 지도 로딩, 완료 후 엔딩과 저장 사진 표시를 수동 확인했다. AndroidRuntime 치명적 오류 로그는 없었다.

증거 화면: `docs/screenshots/01-geographic-map.png`, `docs/screenshots/02-ending.png`. 지도 출처 표시는 유지한다. 엔딩 사진은 가상 카메라 장면이다.

- 품질 게이트: `scripts/verify.ps1` → 단위 테스트 + APK + Lint.
- 기기 게이트: `connectedDebugAndroidTest` → 전체 코스, 단계 재생성/복원, DB 마이그레이션.
- 기기: `FirstStep_API35`, 지정 serial `emulator-5560`. 사용자의 다른 에뮬레이터와 분리한다.
- 단위 테스트: 진행/좌표/입력/센서/방위/HTTP 캐시/Mercator 경계 검증.
- `ThreeMissionFlowTest`: 이름은 초기3미션 테스트에서 유지했으나 후속 버전은 전체5미션과 회전/복원 검증으로 확장했다.
- `DatabaseMigrationTest`: 실제 v1 SQLite 파일을 만들어 v2 Room으로 열고 기존 데이터/사진 경로/모드/중복 방지 유지 확인.
- 자동 테스트의 CARD/HOLD/TYPED는 대체 경로 검증이다. 이를 실제 AR/조도/음성 성공으로 발표하지 않는다.

## 7. 후속 작업 실행 순서

1. `AGENTS.md`, 이 기록, 최신 검증 보고서, Git 상태를 확인한다.
2. 코드/현장 자료를 구분하고 파일 소유권을 지정한다. 현재 하네스는 총괄 → 구현/독립검증 PM → UI/데이터 담당 구조다.
3. 변경 후 관련 단위 검사와 빌드, 필요 시 지정 에뮬레이터 테스트를 실행한다.
4. 테스트 자료를 성공 기록으로 변환하지 않는다. 새 사실이 생기면 읽기 쉬운 요약도 함께 갱신한다.
5. 발표에는 실제 팀원의 담당 기능과 커밋을 별도로 확인해 넣는다. 이번 자동 개발 기록으로 팀원 기여를 추정하지 않는다.

## 8. 에뮬레이터 한글 입력

한글 입력 가능. 에뮬레이터 내부 `설정 → 시스템 → 키보드 → 화면 키보드 → Gboard → 언어 → 한국어` 추가. PC 키보드 한/영 전환은 호스트/에뮬레이터 설정에 따라 다를 수 있으므로 화면 키보드로 확인한다. Gboard가 설치돼 있어도 한국어 배열은 별도 설정일 수 있다. 자동 테스트의 한국어 문자열 입력은 사람의 PC IME 연동을 검증한 것이 아니다.

공식 안내: https://support.google.com/gboard/answer/7068494?hl=ko
