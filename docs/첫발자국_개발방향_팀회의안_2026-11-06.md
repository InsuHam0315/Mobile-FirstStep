# 첫발자국 — 개발 방향·스토리라인 팀 회의안

**작성일:** 2026년 11월 6일  
**회의 목적:** 탐방 이야기와 건물별 미션을 결정하고, 한 달 안에 완성할 범위를 정한다.  
**문서 성격:** 대화와 통합 피드백을 정리한 회의용 초안. 아래 제안은 팀 합의나 구현 완료를 뜻하지 않는다.

---

## 먼저 읽기 · 이번 회의의 핵심

> **첫발자국은 신입생·복학생이 캠퍼스를 탐방하며 “어떤 상황에 어느 시설을 이용하면 되는지” 배우는 앱이다.**

| 항목 | 제안 방향 |
| :--- | :--- |
| 핵심 경험 | 건물 관찰 → 목적에 맞는 활동 → 퀴즈 → 기억 카드 → 다음 장소 |
| 전체 이야기 | **「처음엔 낯설었던 곳들」** — 이름만 알던 건물에 찾아갈 이유를 만든다. |
| 주인공 | 앱을 사용하는 학생 본인. 별도 등장인물은 필수가 아니다. |
| 코스 초안 | **4개 건물·5개 미션.** 실제 동선과 최종 장소는 미확정이다. |
| 챗봇 | Gemini API + RAG로 학교 공식 정보를 설명하고 시설·지도와 연결한다. |
| 비용 방향 | 무료 사용 범위 우선. 사진은 우선 기기에 보관한다. |
| 한 달 목표 | **학교에 시범 도입을 제안할 수 있는 MVP.** 학교 전체의 상시 운영 체계는 후속 과제다. |

### 회의에서 반드시 결정할 다섯 가지

- [ ] 전체 이야기와 건물별 주제에 동의하는가?
- [ ] 4개 건물·5개 미션으로 갈 것인가, 5개 건물로 조정할 것인가?
- [ ] 가장 먼저 완성할 대표 건물과 미션은 무엇인가?
- [ ] 한 달 안에 넣을 기능과 미룰 기능은 무엇인가?
- [ ] 자료 조사·현장 확인·검증을 누가 언제까지 맡을 것인가?

## 1. 교수 피드백을 개발 기준으로 바꾸면

첨부된 통합 피드백은 교수 피드백과 추가 전달 의견, 검토 제안을 구분한 기록이다. 아래는 이를 개발에 적용하기 위한 해석이다.

| 피드백의 핵심 | 우리가 해야 할 일 |
| :--- | :--- |
| 어떤 장소에서 무엇을 하는지 구체적이지 않다. | 건물마다 상황·활동·성공 조건을 한 장으로 정리한다. |
| 기능과 건물이 자연스럽게 연결돼야 한다. | **건물 정보 → 학습 목표 → 활동 → 필요한 기능** 순서로 설계한다. |
| 시설의 역할과 실제 이용 정보를 알려줘야 한다. | 층별 시설·사용 부서·이용 방법을 조사하고 출처를 남긴다. |
| 이야기와 다음 장소가 이어져야 한다. | 다음 시설이 필요한 생활 상황을 제시하고 객관식으로 연결한다. |
| 범위를 지나치게 확장하지 않는다. | 대표 탐방 경험의 완성을 우선하고 챗봇은 안내를 보조한다. |
| 발표가 빽빽하고 경험이 잘 보이지 않는다. | 대표 미션의 실제 APK 화면과 짧은 설명을 중심으로 보여준다. |

**판단 질문:** “이 기능을 사용하고 나면 학생이 이 건물에 대해 무엇을 알게 되는가?”에 답할 수 있어야 한다.

## 2. 스토리라인의 기본 구조

### 이야기 제목 · 「처음엔 낯설었던 곳들」

처음에는 건물 이름만 보이던 캠퍼스 지도에, 탐방을 통해 **‘내가 여기서 할 수 있는 일’**을 하나씩 채워 넣는다.

- **시작:** 장소 이름은 알지만 언제 이용할지 모른다.
- **진행:** 생활 속 상황을 해결하며 장소의 기능과 이용 방법을 알아간다.
- **끝:** 필요한 일이 생겼을 때 다시 찾아갈 수 있는 개인 도감을 얻는다.

페르소나는 “누구를 위해 앱을 설계하는가”를 정리하는 도구다. 실제 탐방에서는 사용자가 주인공이며, 짧은 안내 문장과 환경 관찰만으로 이야기를 진행할 수 있다.

### 시작 화면 문구 예시

> 학교 지도에는 건물 이름이 가득하지만, 아직 내가 찾아갈 이유는 잘 모르겠어요.
>
> 책이 필요할 때, 함께 공부하고 싶을 때, 누군가의 도움이 필요할 때.
>
> 캠퍼스를 걸으며 나에게 필요한 장소를 찾아보세요. 오늘의 첫발자국이 다음 방문의 길잡이가 됩니다.

### 하나의 이야기, 서로 다른 건물별 주제

**자료 찾기 → 함께 공부하기 → 도움받기 → 생활 준비하기 → 나를 돌보기**

각 장소의 주제는 다르지만, 모두 **‘학교를 스스로 이용할 수 있게 되는 과정’**으로 연결된다. 실제로 하루 안에 대출·상담·증명발급·진료를 모두 받아야 하는 설정은 아니다. 앞으로 그런 일이 필요할 때 사용할 방법을 배우는 탐방이다.

## 4. 건물별 이야기와 미션 예시

### ① 중앙도서관 · 스스로 찾아보는 힘

> “첫 과제에 필요한 자료를 찾아야 합니다. 학교에서 도움받을 방법을 찾아볼까요?”

| 항목 | 설계 예시 |
| :--- | :--- |
| 활동 | 공개된 건물 표식 확인 → 촬영이 허용되면 사진 기록 → 자료 대출 안내 확인 |
| 학습 목표 | 자료를 빌릴 수 있는 곳과 창구 대출 준비물을 안다. |
| 기능을 쓰는 이유 | 카메라로 표식을 직접 관찰하고 나중에 다시 볼 기록을 남긴다. |
| 완료 조건 | 사진 또는 관찰 대체 활동 확인 + 시설 복습 정답 |
| 보상 | ‘자료 찾기’ 기억 카드와 공식 이용 안내 링크 |

**복습 예시:** 창구에서 자료를 대출할 때 필요한 행동은?  
① 본인 신분증과 자료 제시 · ② 반납함에 넣기 · ③ 책 표지만 촬영하기  
**정답:** ①. 사진 촬영은 자료 대출이나 건물 자동 인증을 대신하지 않는다.

**다음 장소로 이어지는 문장**

> “자료를 찾는 방법을 알아냈어요. 이번에는 친구들과 자료를 펼쳐 놓고 이야기할 공간이 필요합니다.”

**다음 시설 선택:** 보건진료소 / **황룡도서관** / 학생생활관

### ② 황룡도서관 · 함께 배우는 공간

> “혼자 집중할 때와 함께 토론할 때는 필요한 공간이 다릅니다. 우리 팀이 이용할 공간을 찾아보세요.”

| 항목 | 설계 예시 |
| :--- | :--- |
| 활동 | 공개 안내도·공식 안내에서 그룹스터디룸 찾기 → 이용 방법 확인 |
| 학습 목표 | 학습 목적에 맞는 공간을 고르고 이용 전 확인할 정보를 안다. |
| 기능을 쓰는 이유 | 안내도 확인과 화면 선택으로 공간의 용도를 구분한다. |
| 완료 조건 | 상황에 맞는 공간 선택 + 시설 복습 정답 |
| 보상 | ‘함께 공부하기’ 기억 카드 |

**복습 예시:** 친구들과 팀플 공간을 알아볼 때 먼저 확인할 곳은?  
① 그룹스터디룸 이용 안내 · ② 증명서 발급 안내 · ③ 보건 서비스 안내  
**정답:** ①. 실제 예약·입실 완료와 안내 확인은 구분한다.

**다음 장소로 이어지는 문장**

> “공부할 공간을 알아두었어요. 학교생활을 하다 보면 무엇을 준비하고 어디로 나아갈지도 고민하게 됩니다. 함께 방향을 찾아줄 곳은 어디일까요?”

**다음 시설 선택:** **대학일자리플러스센터** / 보건진료소 / 학생생활관

### ③ 제2학생회관 · 혼자 해결하지 않아도 되는 일

이 건물은 두 가지 학생 지원 기능을 하나의 에피소드 안에서 익힌다.

**미션 A · 진로에 관한 도움 찾기**

> “앞으로 무엇을 준비해야 할지 막막할 때, 학교에서 받을 수 있는 도움을 찾아보세요.”

- **활동:** 공식 센터 안내를 보고 관심 있는 상담·지원 항목을 선택한다.
- **학습 목표:** 진로·취업 상담과 관련 프로그램을 어디서 알아볼지 안다.
- **완료 조건:** 지원 항목 선택 + 시설 복습 정답.
- **복습 예시:** 이곳에서 알아볼 수 있는 도움은? → **진로·취업 상담과 지원 프로그램**.
- **보상:** ‘방향 찾기’ 기억 카드.

음성 기능을 넣는다면 외부의 발화 가능한 장소에서 문의 표현을 연습하는 선택 활동으로 검토한다. 문자로도 진행할 수 있어야 하며, 실제 상담 신청이 완료됐다고 표시하지 않는다.

**미션 B · 필요한 서류 준비하기**

> “학교의 도움은 상담만 있는 게 아니에요. 재학증명서가 필요할 때 이용할 방법도 알아볼까요?”

- **활동:** 공개 안내에서 증명서 종류와 방문·인터넷 발급 경로를 확인한다.
- **학습 목표:** 증명서가 필요할 때 이용할 방법을 안다.
- **완료 조건:** 상황에 맞는 발급 경로 선택 + 시설 복습 정답.
- **복습 예시:** 학교 방문이 어려울 때 공식 안내에서 확인할 다른 발급 방법은? → **인터넷 증명발급**.
- **보상:** ‘학교생활 준비하기’ 기억 카드.

실제 로그인·결제·출력은 완료 조건에서 제외한다. 발급기 화면과 출력물의 개인정보를 촬영하지 않는다.

**다음 시설 선택:** “교내 건강상담 안내는 어디서 알아볼까요?” → **보건진료소**

### ④ 제1학생회관 · 나를 돌보는 학교생활

> “공부하고 준비하는 것만큼 내 상태를 살피는 것도 학교생활의 일부입니다. 건강에 관한 도움을 알아볼 곳을 찾아보세요.”

| 항목 | 설계 예시 |
| :--- | :--- |
| 활동 | 공개 안내에서 보건진료소의 위치와 서비스 확인 |
| 학습 목표 | 건강상담 등 교내 보건 안내를 어디서 찾을지 안다. |
| 완료 조건 | 시설 복습 정답 |
| 복습 예시 | 보건진료소에서 알아볼 수 있는 서비스는? → 건강상담 등 보건 서비스 |
| 보상 | ‘나를 돌보기’ 기억 카드와 전체 탐방 정리 |

진료받기·건강정보 입력·진료 공간 촬영은 요구하지 않는다. 마지막 장소에서는 다음 시설 문제 대신 전체 도감으로 마무리한다.

## 5. 엔딩과 재사용

### 끝났을 때 사용자가 얻는 것

건물 이름만 보이던 지도에 **‘자료를 찾는 곳 / 함께 공부할 곳 / 진로 도움을 받을 곳 / 서류를 준비할 방법 / 건강 도움을 알아볼 곳’**이 남는다.

> 처음에는 이름만 알던 건물에 이제는 찾아갈 이유가 생겼어요.
>
> 오늘의 탐방은 끝났지만, 여러분의 학교생활은 여기서 이어집니다.

도감에는 시설의 기능, 확인한 이용 방법, 공식 링크, 허용된 탐방 사진을 저장한다. 탐방을 다시 처음부터 하지 않아도 시설 정보와 즐겨찾기를 열 수 있게 한다.

**재사용의 이유:** 스탬프를 다시 모으는 것뿐 아니라, 실제로 도움이 필요한 순간 저장한 장소와 안내를 다시 찾는 데 있다.

## 6. 스마트폰 기능은 어떻게 선택할까?

| 기능 | 사용할 목적 | 구분할 점 |
| :--- | :--- | :--- |
| GPS | 검증된 건물 주변 도착 확인 | 실내 층을 판정하는 기능으로 설명하지 않는다. |
| 카메라 | 건물 표식 관찰·개인 탐방 기록 | 현재 OCR·자동 건물 인식은 없다. |
| 방향 센서 | 다음 장소 방향 익히기 | 현재 방향 구현을 직접 자이로 측정이라고 설명하지 않는다. |
| 음성 | 필요한 표현·시설명에 관한 선택 활동 | 정숙 공간에서는 문자로 진행한다. |
| 조도·가속도 | 학습상 이유가 분명할 때 채택 | 손가림·폰 흔들기를 필수 미션으로 유지할지는 재검토한다. |
| AR | 현장에 연결된 기억 발견 연출 | 실제 추적 성공 검증과 일반 카드 대체를 구분한다. |

**AR가 실패해도 탐방은 완주할 수 있어야 한다.** 조도·자이로 등 특정 센서 사용이 과목의 필수 평가 항목인지 확인하고, 필수라면 그에 맞는 활동을 다시 설계한다.

## 7. 챗봇과 무료 우선 구성

### 챗봇의 역할

**목표:** 학교생활 전반의 질문을 공식 자료에 근거해 설명하고, 시설·지도·저장 기능으로 연결한다.

예: “진로 상담 어디서 받아?” → 공식 안내와 출처 → 시설 카드 → 위치 보기·즐겨찾기.

- Gemini API + RAG를 기본 방향으로 한다.
- 초기에는 시설·학생지원·증명발급 등 검증 가능한 자료부터 연결한다.
- 학사·장학·공지 등으로 확대할 때 연도·학기·마감일을 확인한다.
- 자료가 없거나 상충하면 확인이 필요하다고 안내한다.
- 개인 성적·시간표 조회는 별도의 학교 인증·API 협의가 필요한 범위다.

### 비용을 줄이는 목표 구성

| 항목 | 무료 우선 선택 | 한계 |
| :--- | :--- | :--- |
| 로그인 | Firebase Authentication의 Google 로그인 | 프로젝트 설정과 실제 로그인 검증 필요 |
| 사용자·미션 기록 | Firestore Spark | 무료 저장·읽기·쓰기 한도 내 운영 |
| 사진 | 기기 내 파일 + Room | 다른 기기로 사진 자동 복원 불가 |
| 챗봇 | Gemini 무료 지원 모델 + RAG | 계정별 제공 모델·호출량·검색 용량 확인 필요 |
| 챗봇 중계·자료 갱신 | 팀 PC의 기존 FastAPI | PC 전원과 네트워크가 필요. 상시 운영 서버는 아님 |

Cloud Storage와 배포형 Cloud Functions는 초기 무료 구성에서 제외한다. Gemini 키는 앱에 넣지 않는다. 무료 챗봇 사용량이 소진되면 공식 자료 검색·FAQ를 제공한다. 공개 학교 자료 중심으로 사용하고 민감한 개인 정보를 보내지 않는다.

**구분:** 무료로 개발·시연하는 것과 학생들에게 상시 서비스를 제공하는 것은 다른 목표다. 요금·한도는 설정 시 공식 문서와 실제 계정에서 다시 확인한다.

## 8. 한 달 안에 어디까지 만들 것인가?

> **목표: 대학 담당자에게 시범 도입을 제안할 수 있는 탐방 앱과 최소 관리 기능.**

B2B 확장은 학교가 콘텐츠를 관리하고 학생에게 제공할 수 있는 방향을 뜻한다. 계약·학교 시스템 연동·대규모 상시 운영까지 한 달 안에 완료한다고 전제하지 않는다.

| 주차 | 우선 작업 | 확인할 결과 |
| :--- | :--- | :--- |
| 1주차 | 건물 정보와 이야기 확정, 대표 미션 1개 완성 | 시작→활동→퀴즈→저장→재개가 연결되는 실제 APK |
| 2주차 | 검증된 장소로 3~5개 미션 확장, 로그인·기록 동기화 | 사용자·테스트/현장 기록 분리, 재실행 후 복원 |
| 3주차 | 제한된 자료 기반 챗봇, 최소 담당자 관리 기능 | 출처 있는 답변, 시설·미션 설명 수정 및 공개 여부 관리 |
| 4주차 | 사용자 시험·오류 수정·발표 화면 확보 | 대표 흐름과 실패·대체 흐름의 검증 기록 |

위 일정은 자료 조사·접근 가능한 현장·기기 확보가 병행된다는 조건의 추정이다. 대표 미션이 안정화되지 않으면 챗봇 범위와 관리자 기능을 줄여 핵심 탐방을 먼저 완성한다.

**이번 달 보류:** 커뮤니티, 여러 대학 동시 운영, 학교 포털 SSO, 개인 학사정보 연동, 모든 학교 질문에 대한 답변 보장, 대규모 운영 체계.

## 9. 현재 구현과 앞으로 할 일을 구분하기

2026-11-05 개발 검토·검증 기록을 기준으로 정리했다. 이 문서 작성만으로 새로운 기능이 구현된 것은 아니다.

| 구분 | 상태 |
| :--- | :--- |
| 기존 탐방 기반 | 5개 미션·저장·도감·테스트/현장 모드 코드가 있다. 새 이야기와 건물별 미션으로 수정해야 한다. |
| 카메라 | 에뮬레이터 가상 장면의 CameraX 촬영·JPEG 저장을 확인했다. 실제 캠퍼스 촬영 검증과 다르다. |
| 지도 | 군산대 주변 지도와 주입한 테스트 위치 표시를 확인했다. 현장 도착 좌표는 미검증이다. |
| AR | 코드가 있으나 해당 검증 환경에서 평면 추적·배치 성공은 미확인이다. |
| 시설 안내 | 공식 출처를 연결한 시설 검색·기기 내 즐겨찾기 화면을 추가했다. |
| Firebase 전환 | 제안 단계. 현재 서버의 MySQL 기반 구현을 이미 이전한 것은 아니다. |
| Gemini RAG | 설계 단계. 모델 연결·공식 자료 수집·답변 검증은 남아 있다. |
| 관리자 화면 | 한 달 범위의 제안. 구현 완료가 아니다. |

실제 APK 화면은 에뮬레이터에서도 확보할 수 있다. 현장 GPS·센서·AR 성능 검증에는 실제 환경과 기기가 필요하므로 대여·학교 장비 활용 가능성을 확인한다.
