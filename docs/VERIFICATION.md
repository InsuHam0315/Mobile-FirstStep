## 연속 세 미션 테스트

`ThreeMissionFlowTest`는 완료 DB를 직접 채우지 않고 실제 화면 입력으로 다음 흐름을 실행한다.

1. 테스트 기록 초기화와 닉네임 설정.
2. M01: 일반 카드 발견 → 이야기 → CameraX로 에뮬레이터 장면 촬영 → 사진 확인 → 시설 질문 → 완료 저장.
3. M02: 일반 카드 → 이야기 → 버튼 3.2초 유지 대체 조작 → 시설 질문 → 완료 저장.
4. M03: 일반 카드 → 안내 문구 → 한국어 `생활` 직접 입력 → 시설 질문 → 완료 저장.
5. Room에서 3개 완료와 `CARD`, `PHOTO/HOLD/TYPED` 방식 확인, 촬영 JPEG 존재와 이미지 크기 확인, 현장 기록 0개 확인.
6. Activity 재생성 후 `3 / 5 완료` 복원 확인.

카드·길게 누르기·텍스트를 사용한 이 결과는 AR 추적·조도 하드웨어·음성 인식 자체의 검증이 아니다. 카메라 사진은 에뮬레이터 가상 장면이며 실제 캠퍼스 사진이 아니다.

## 총괄 수동 실행 확인

- 앱 프로세스를 강제 종료하고 다시 실행한 뒤 `3 / 5 완료` 복원.
- 코스 안내도 화면 열기, 5개 노드 표시, 실제 지도가 아닌 도식이라는 문구 확인.
- 시설 도감에서 완료 기록과 CameraX 촬영 이미지 표시.
- 도감 검색어 `zzz`로 일치하지 않는 시설이 제거되는 것 확인. 빈 결과 안내 문구를 추가했다.
- 현장 모드 전환 시 `0 / 5 완료`, 미검증 장소 시작 차단 대화상자 확인.
- 테스트 모드로 돌아오면 기존 테스트 기록 유지.
- 긴 후보 장소명을 화면에 맞게 줄이고, 내부 `CARD` 표시는 `일반 카드 발견`으로 바꾼 뒤 빌드·단위 테스트·Lint를 다시 통과했다.
- AndroidRuntime 로그에서 앱 치명적 오류 없음.

검증 스크린샷은 로컬 `tmp/qa/`에 보관하며 Git에 포함하지 않는다.

## 수정하면서 확인한 오류

- 안내도 XML 내부 클래스 표기: `$` 이름을 사용하는 `view class` 방식으로 수정 후 화면 열기 확인.
- CameraX 중복 입력/종료 후 콜백: 촬영 중 비활성화와 세대 번호 검사, 임시 사진 정리.
- DB 저장 전 보상 표시: 저장 성공 후 완료 화면으로 변경.
- AR 서비스 자동 설치로 대체 카드 진입 방해: 명시적인 `AR로 찾기`를 눌렀을 때만 서비스/권한 확인.
- 오래 끊긴 위치 수신을 연속 체류로 인정하는 문제: 5초 초과 수신 공백 시 초기화.
- 한 움직임 중복 집계와 수평 이동 감도: 중력 벡터 제거, 임계값 복귀·시간 간격·준비 시간 적용.
- 사진 방향/누락: EXIF 보정, 축소 로딩, 누락 파일 안내.

## 검증되지 않았거나 후속인 항목

- 실제 군산대 장소 좌표·출입구·보행 경로·세부 시설 정보. 모두 후보이며 현장 미션은 차단 상태.
- AR 지원 실기기의 평면 추적, 앵커, 오브젝트 선택과 CameraX 전환.
- 실기기 조도·가속도 임계값, GPS 도착, 한국어 TTS/음성 인식 서비스.
- M04 실제 목표 방위 센서 판정. 현재 명시적인 대체 조작으로 연결.
- 실제 캠퍼스 지리 지도. 현재 안내도는 순서도.
- Room v1→v2 마이그레이션은 코드/빌드 확인, 이전 버전 DB를 넣는 별도 기기 테스트는 미실행.
- 미완료 미션의 회전/프로세스 재생성 시 세부 단계 복원은 미제공. 완료 기록은 유지되고 미완료 미션은 다시 발견한다.

따라서 중간 단계의 주요 화면과 최소 3개 미션 통합을 실행 가능한 상태로 검증했으며, **최종 현장 서비스 전체 완성**을 주장하지 않는다.
