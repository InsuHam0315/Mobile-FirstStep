# 검증 기록

검증일: 2026-11-02 (Asia/Seoul). 대상: FirstStep 후속 구현 소스와 디버그 APK. 자동 검사, 총괄 수동 확인, 실제 기기·현장 검증을 구분한다.

## Android Studio Run 환경 복구

2026-11-02 사용자 실행 문제를 추가 확인했다. Pixel 10 Pro API 37.2에서 MainActivity는 실행됐고 UI 계층에는 닉네임 입력 화면이 있었지만 화면 캡처는 검정색이었다. 앱 치명적 예외는 발견되지 않았으며 앱 재실행으로 해결되지 않았다. 해당 AVD의 정확한 렌더링 결함 원인은 확정하지 않았다.

발표용 `FirstStep_API35`의 공식 API 35 revision 9 이미지 파일은 존재했으나 Studio 설치 메타데이터가 누락돼 Run에서 Missing system image가 발생했다. Google 공식 저장소의 동일 버전 메타데이터로 등록 정보를 복구하고 Studio를 재시작했다. 발표용 AVD의 그래픽은 검증 당시와 같은 `swiftshader_indirect`로 설정했다. Studio 상단 실행 대상을 **FirstStep API 35 QA**로 선택한 뒤 실제 Run으로 부팅·빌드·설치·홈 표시와 도감 탭 이동을 확인했다. 기존 5개 완료 기록은 유지했고 데이터를 초기화하지 않았다. 재시작 후 ADB serial은 배정에 따라 바뀔 수 있으므로 기기 이름으로 구분한다.

## 연속 5개 미션과 복원 검사

`ThreeMissionFlowTest`라는 기존 클래스 이름을 유지하지만, 현재 검증 범위는 5개 미션이다. 완료 DB를 직접 채우는 대신 화면을 통해 다음 흐름을 실행한다.

1. 테스트 기록 초기화와 닉네임 설정.
2. M01: 일반 카드 발견 → 이야기 → CameraX 촬영 → 사진 확인 → 시설 질문 → 저장. 사진 확인 화면을 재생성해 단계 복원을 확인한다.
3. M02: 일반 카드 → 이야기 → 3초 길게 누르기 대체 조작 → 시설 질문 → 저장. 미완료 누르기 중 재생성 후 진행을 다시 시작한다.
4. M03: 일반 카드 → 안내 문구 → 한국어 `생활` 직접 입력 → 시설 질문 → 저장. 일부 입력 상태를 재생성해 보존 여부를 확인한다.
5. 3개 완료 기록의 `CARD`, `PHOTO/HOLD/TYPED` 방식, 촬영 JPEG의 존재와 이미지 크기, 현장 기록 0개, 홈 재생성 후 진행 복원을 확인한다.
6. M04와 M05를 길게 누르기 대체 조작과 시설 질문으로 완료하고, 5개 기록·방식·현장 모드 분리를 확인한다.
7. 이미 저장된 M01에 `SAVING` 체크포인트를 복원하여 기존 사진·완료 시각을 유지하고 중복 보상을 만들지 않는지 확인한다.

`MissionCheckpointStoreTest`는 DB에 아직 저장되지 않은 `SAVING` 사진을 모드 초기화 시 정리하고 다른 모드 체크포인트를 보존하는지 확인한다. `DatabaseMigrationTest`는 실제 v1 형식 DB를 만들어 v2로 열고, 기존 사진·시간·발견 방식·모드 기록 및 `LEGACY` 완료 방식, 중복 삽입 방지를 확인한다. 테스트용 DB를 사용하며 실제 사용자 DB를 대체하지 않는다.

카드·길게 누르기·직접 입력 결과는 AR 추적·조도·방향·가속도 하드웨어·음성 인식 자체의 검증이 아니다. CameraX 사진은 에뮬레이터 가상 장면이며 실제 캠퍼스 사진이 아니다. Activity 재생성 검사는 갑작스러운 프로세스 종료의 모든 시점을 검증한 것으로 해석하지 않는다.

## 후속 구현의 소스 확인 범위

- OpenStreetMap 지리 지도와 별도 탐방 순서도: 현재 뷰포트만 요청, 앱 식별 User-Agent, 출처 표시, HTTP 캐시·조건부 요청, 종료 시 연결 정리. 지도에 쓰는 공개 중심값은 미션의 현장 검증 좌표와 분리한다.
- 방향센서: 회전벡터 우선과 가속도+자기장 대체, 화면 회전 보정, 정확도·측정 최신성, 방위 유지 판정. 테스트 모드는 자북 연습이며, 현장은 신선한 도착 위치와 다음 검증 지점으로 진북 기준 목표를 계산한다.
- 체크포인트: 모드별 단계·사진 확인·입력 보존, 저장 중 Room 결과 확인, DB 소유 사진 보호와 미참조 임시 사진 정리. 위치와 센서 유지 진행값은 완료 증거로 복원하지 않는다.
- 현장 복귀: 백그라운드에서 돌아오면 도착을 다시 확인한다. 오래된 도착 위치로 방향 미션을 시작하지 않는다.
- 마지막 이야기: 요청한 모드의 저장 기록을 읽으며 화면 열기만으로 보상을 부여하지 않는다.

독립 검토의 발견 사항과 수정 확인은 [후속 검토 기록](REVIEW_CONTINUATION.md)에 있다. 지도 서비스 이용 조건은 [OSMF 정책](https://operations.osmfoundation.org/policies/tiles/)을 기준으로 확인했다.

## 최신 APK 총괄 직접 확인

총괄이 최신 APK에서 연속 5개 미션 instrumentation을 재실행한 뒤 다음을 수동 확인했다.

- 앱을 강제 종료하고 다시 실행해 `5 / 5 완료` 기록 유지.
- 실제 OpenStreetMap 지도 타일 로드와 출처 표시.
- 마지막 이야기 화면과 저장된 사진 표시. 사진은 에뮬레이터 가상 장면이다.
- 해당 확인 중 AndroidRuntime 치명적 오류 로그 없음.

증거: [지리 지도](screenshots/01-geographic-map.png), [마지막 이야기](screenshots/02-ending.png). 지도 스크린샷에는 출처 표시가 포함되어 있다. 이 확인은 네트워크 실패·권한 거절·실제 현장 이동의 모든 분기를 검사한 것은 아니다.

## 이전 중간 범위의 수동 실행 기록

다음은 후속 구현 이전의 **3개 미션 버전**에서 총괄이 확인한 과거 결과다. 최신 지리 지도·마지막 이야기·5개 미션의 직접 확인은 위 항목을 기준으로 한다.

- 앱 프로세스 강제 종료 후 `3 / 5 완료` 복원.
- 당시 개념 순서도의 5개 노드 및 실제 지리 지도가 아니라는 안내 확인.
- 시설 도감의 완료 기록·CameraX 이미지, 검색 결과 제거 확인.
- 현장 모드 `0 / 5 완료`와 미검증 장소 시작 차단, 테스트 기록 유지 확인.
- 당시 실행의 AndroidRuntime 치명적 오류 없음.

기존 검증 자료는 로컬 `tmp/qa/`에 보관하며 Git에 포함하지 않는다. 위 최신 대표 스크린샷은 `docs/screenshots/`에 보관한다.

## 실제 기기·현장에 남은 검증

- 실제 군산대 장소 좌표·출입구·보행 경로·시설명·안내 내용. 모든 미션은 현재 후보 좌표 `null`, `coordinateVerified=false`이며 현장 시작은 차단된다.
- AR 지원 실기기의 평면 추적·앵커·오브젝트 선택과 CameraX 전환.
- 실제 캠퍼스 표식 촬영, 조도·가속도 임계값, 방향센서 정확도·자기장 간섭·실제 목표 방위.
- GPS 도착·체류·이탈·권한 거절·위치 수신 중단과 현장 복귀.
- 한국어 TTS·음성 인식 제공자별 동작과 네트워크 처리.
- 지도 네트워크 실패·캐시 만료·연결 끊김·권한 거절 등 기기별 분기.
- 프로세스가 임의 시점에 종료되는 모든 저장·사진 촬영 경쟁과 기기별 생명주기 동작.

후속 구현, 에뮬레이터 자동 검사, 대표 화면의 직접 확인을 완료했다. 최종 현장 서비스 검증은 별도다.
