# 첫발자국 — PPT 제작용 개발 요약

작성 기준: 2026년 11월 2일. 실제 구현과 검증 내용을 바탕으로 만든 발표 재료다. PPT 파일 자체는 별도 제작 대상이다.

## 프로젝트를 한 문장으로

**첫발자국은 캠퍼스를 직접 탐방하며 사진·빛·음성·방향·움직임 미션을 수행하고, 시설 정보와 방문 기억을 도감에 남기는 Android 앱이다.**

주요 대상은 국립군산대학교 신입생이며, 낯선 시설을 알아보려는 재학생도 참여할 수 있다. 목표는 학교 시설의 위치와 용도를 경험으로 익히게 하는 것이다. 실제 학습 효과는 이후 사용자 테스트로 확인해야 한다.

## 제안에서 실행 가능한 앱으로

처음에는 장소 이동과 센서 게임을 연결하는 아이디어였다. 현재는 닉네임 입력부터 코스 선택, 발견, 이야기, 미션, 시설 질문, 저장, 도감, 마지막 탐방 기록까지 화면과 기능이 연결되어 있다.

교수 피드백을 반영한 기획서의 **5개 장소·한 편의 이야기**를 기준으로 개발했다. 이전 제안 자료에 적힌 6개소·10개 미션과 현재 구현 수치를 섞지 않는다.

## 사용자가 경험하는 흐름

**시작 → 코스 확인 → 장소 확인 → 기억 발견 → 미션 수행 → 시설 질문 → 보상·저장 → 다음 장소 → 탐방 기록**

테스트 모드에서는 위치 확인을 건너뛰어 강의실에서도 흐름을 확인할 수 있다. 테스트 기록과 현장 방문 기록은 서로 분리된다.

## 다섯 미션

| 기억 | 사용자가 하는 일 | 배우는 내용 | 어려울 때 |
| --- | --- | --- | --- |
| 1. 수업의 기억 | 건물 표식을 촬영하고 사진 확인 | 건물 이름과 수업 공간 연결 | 권한 안내·재촬영 |
| 2. 배움의 기억 | 밝기 센서를 가렸다가 다시 열기 | 도서관의 학습·자료 이용 역할 | 3초 길게 누르기 |
| 3. 생활의 기억 | 안내를 듣거나 읽고 핵심 단어 답하기 | 생활시설 정보 확인 방법 | 직접 글자로 입력 |
| 4. 방향의 기억 | 목표 방향으로 휴대전화를 돌려 유지 | 지도와 실제 방향의 관계 | 길게 누르기 |
| 5. 활력의 기억 | 안전하게 멈춰 기기를 가볍게 움직이기 | 활동·휴식 공간의 이용 목적 | 길게 누르기 |

모든 미션은 조작만 끝내고 지나가지 않는다. 마지막에 시설 질문에 답하고 설명을 확인한 뒤 기록한다. 실제 시설명·출입구·세부 안내는 현장 확인 전 후보 내용이다.

## 이번에 추가한 기능

### 실제 방향을 읽는 나침반

방향센서와 화면의 회전 방향을 반영해 현재 방향을 보여 준다. 목표에 맞춰 일정 시간 유지하면 성공한다. 테스트에서는 자북을 맞추는 연습을 하고, 현장에서는 검증된 다음 장소를 향하는 방위를 계산하도록 구현했다.

### 실제 지리 정보를 보여 주는 지도

OpenStreetMap을 이용해 군산대학교 주변 지도를 확대·축소하고 이동할 수 있다. 위치 권한을 허용하면 현재 위치와 오차 범위를 표시한다. 기존 탐방 순서도도 별도로 볼 수 있다. 아직 현장 확인하지 않은 미션 지점은 임의로 지도에 찍지 않는다.

### 중단 후 이어하기

화면을 돌리거나 앱이 다시 만들어져도 이야기, 사진 확인, 질문, 입력한 글을 이어갈 수 있도록 했다. 센서 측정은 새로 시작하고, 현장 모드는 위치를 다시 확인한다. 이미 저장한 사진이 복원 과정에서 삭제되지 않도록 보완했다.

### 다섯 기억을 모은 뒤의 마무리

모든 미션을 마치면 마지막 이야기와 장소별 기록, 촬영 사진을 모아 볼 수 있다. 보상은 저장된 완료 기록을 기준으로 표시한다.

## 구현 기술을 설명하는 방법

| 기술 | 앱에서 맡는 역할 |
| --- | --- |
| Java + XML | Android 네이티브 화면과 동작 |
| CameraX | 사진 미리보기·촬영·확인·저장 |
| ARCore | 평면 인식, 기억 조각 배치와 선택 |
| 위치 API | 현재 위치와 도착 조건 확인 |
| 조도·가속도·방향센서 | 사용자의 행동을 게임 입력으로 연결 |
| TTS·음성 인식 | 안내를 듣고 말로 답하기 |
| Room | 완료 기록과 사진 경로를 기기에 보관 |
| 로컬 체크포인트 | 중단한 미션 단계 복원 |
| 네이티브 지도 | 실제 지도와 검증된 지점 표시 |

AR을 사용할 수 없으면 일반 카드로 발견한다. 카드 방식은 AR 성공으로 기록하지 않는다. 사진 촬영도 자동 건물 인식 기능은 아니다.

## 검증에서 확인하는 것

- 미션을 순서대로 완료하고 다음 미션이 열리는가.
- 사진이 실제로 생성되고 도감에 다시 나타나는가.
- 테스트 기록이 현장 기록에 섞이지 않는가.
- 화면 회전·재실행 후 기록과 진행을 복원하는가.
- 저장 버튼이나 콜백이 중복돼도 보상이 두 번 생기지 않는가.
- 이전 버전 DB를 새 버전으로 바꿔도 기록이 유지되는가.
- 센서 판정이 경계값·시간 조건·신호 중단을 처리하는가.

| 최종 검사 | 결과 |
| --- | --- |
| 기능 판정 단위 검사 | 34개 통과 |
| 에뮬레이터 기기 검사 | 4개 통과 |
| 앱 설치 파일 생성 | 성공 |
| Android 정적 검사 | 오류 0개·경고 78개 |
| 최종 앱 재확인 | 5미션 통합 검사 재통과, 재실행 후 5개 기록 유지, 지도·엔딩·사진 표시 확인 |

4개 기기 검사에는 기본 패키지 검사 1개가 포함된다. 나머지는 전체 미션과 화면 복원, 미완료 사진 정리와 모드 분리, 이전 DB의 기록 유지 검사다. 경고 78개는 남아 있는 개선 항목이다. 실제 센서·AR·현장 도착을 모두 검증했다는 뜻은 아니다.

## 직접 수정한 문제 사례

| 발견한 문제 | 수정 방향 |
| --- | --- |
| 저장 전에 완료 화면이 먼저 표시됨 | 저장 성공 후 보상 표시 |
| 촬영 중 중복 입력·늦은 콜백 | 입력 잠금과 화면 생명주기 확인 |
| 화면 복원 중 완료 사진 삭제 가능성 | DB 기록과 사진 소유권 확인 후 정리 |
| 위치가 오래 끊겨도 체류로 계산 | 최신성·수신 간격 확인 후 판정 초기화 |
| 센서 측정이 한 번의 동작을 반복 집계 | 중력 제거, 임계값 복귀, 시간 간격 적용 |
| AR 서비스 설치가 대체 진행을 방해 | AR 시작을 사용자가 선택하도록 변경 |

## 발표에서 명확히 구분할 점

**구현한 것:** 미션 화면과 판정 코드, 저장·복원, 네이티브 지도, AR 및 대체 경로, 다섯 미션 연결.

**에뮬레이터에서 확인한 것:** 촬영과 대체 조작을 포함한 플레이 흐름, 기록 분리, 단계 복원, 데이터 저장 검사. 가상 카메라 장면을 실제 캠퍼스 촬영이라고 표현하지 않는다.

**현장·실기기가 필요한 것:** 정확한 미션 장소와 좌표, 안전한 이동 경로, 실물 환경의 AR 추적, GPS 오차, 센서 감도, 실제 한국어 음성 서비스, 사용자 반응.

앱 사용으로 시설 이해가 향상됐다는 효과나 학교 운영 도입이 확정됐다는 주장은 아직 하지 않는다.

## PPT 구성에 옮기기 좋은 순서

1. 목적: 낯선 캠퍼스를 직접 경험하며 익히기.
2. 전체 흐름: 시작부터 도감·엔딩까지.
3. 주요 화면: 코스, 지도, 사진, 센서, 도감.
4. 대표 미션: 사용자의 행동 → 판정 → 시설 질문 → 저장.
5. 구현 구조: 화면·장치·판정·저장의 역할.
6. 개발 중 해결한 문제와 검증 근거.
7. 지금 가능한 시연과 실제 기기·현장 검증 계획.

팀원별 역할과 커밋 수는 실제 사람의 개발 기여를 확인해 별도로 넣는다. 자동 개발 도구의 작업 분담을 팀원의 실적처럼 사용하지 않는다.

## 실행 및 시연 준비

Android Studio에서 기존 `FirstStep` 프로젝트를 열고 `FirstStep_API35` 또는 실제 Android 기기로 실행한다. 테스트 모드, 일반 카드 발견, 사진 촬영, 센서 대체 조작, 직접 입력을 사용하면 지원 기기 차이에 덜 영향을 받는 흐름을 확인할 수 있다. 실제 센서/AR 시연은 검증한 기기에서 따로 보여 준다.

에뮬레이터에서 한글이 입력되지 않으면 내부 Gboard에 한국어를 추가하고 화면 키보드를 사용한다.
