## Goal, behavior, and rationale

H01 establishes a replaceable Java/XML presentation foundation inside the existing app module. A separate debug launcher, **게임 미리보기**, loads explicitly labeled simulated content without camera, location, or network. Selecting the sample updates screen state. Its stable selection ID survives Activity recreation, stop/start, and observed rotation; it is transient Bundle state, not durable game progress. Unknown restored IDs are discarded when fresh content arrives.

Java 11 POJOs/interfaces keep contracts and coordination Android-independent. Existing AppCompat/Material Views plus XML resources avoid a new UI framework or dependencies. Composition owns background/main executors and cancellation; UI binds state, forwards actions, applies insets, and saves the transient ID. No game policy, storage, clock, sensor, network, or permission operation is implemented in presentation. There are no one-shot device/navigation effects in this slice; rendering sets View properties/listeners only.
