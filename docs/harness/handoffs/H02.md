## Behavior and technology

Pure Java immutable aggregates and a synchronous repository port keep rules independent of Android presentation. `ProgressService` accepts a clock and an attempt-ID/shuffle factory; Room implements atomic persistence using the project's existing dependencies. Versioned asset JSON provides configurable IDs, Korean fixture labels, questions and options. No new dependency, manifest, build, UI, or legacy source modification was needed.

- Each `(NORMAL|DEMO, buildingId)` progresses independently. First introduction completion time is preserved on replay; NORMAL eligibility is timestamp + 900000ms. Instant eligibility is explicitly DEMO-only. Notifications do not determine eligibility.
- Three questions use stable question/option IDs. At least two correct answers pass. Each attempt persists content version and the full ordered question/option/answer-key snapshot. Restart restores the active attempt, including after a backward clock change; grading uses that snapshot even when catalog content changes.
- Failure creates an immediate shuffled retry. Identical repeated submissions return the previous result without another retry or stamp; conflicting submissions fail. Submission history and its single stamp are saved together in a Room transaction. Two independent database handles submitting concurrently are tested.
- Catalogs accept 1–5 unique buildings with exactly three questions each. Empty/oversized catalogs are rejected. Only five distinct known stamps within the requested mode unlock the ending; unknown IDs and the other mode do not count.
- Only full submissions persist answers. Individual in-progress answer selections are not saved by this contract.
