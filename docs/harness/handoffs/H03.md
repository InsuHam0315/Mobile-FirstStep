## Behavior and technologies

The additional debug launcher **발견 체험** opens a real CameraX preview with a replaceable 2D placeholder character. Camera permission denial, missing/unusable devices and initialization failure expose retry, camera-free continuation and exit. Direction can use the rotation-vector sensor or an explicitly labeled manual alternative. Every arrival is explicitly simulated; this is not GPS arrival, tracked AR or campus footage.

Java 11 state/controller classes keep thresholds and lifecycle decisions outside Views. XML/AppCompat Views reuse H01 resource tokens; separate strings/artwork allow later visual replacement. Existing CameraX 1.4.2 dependencies are reused without build dependency changes. Android adapters own CameraX, SensorManager, display-coordinate remapping and monotonic time; the controller receives injected time and session-tagged observations. Failed registrations are unavailable, and close is idempotent.

SHAKE identifies `digital_information_software`; LIGHT identifies `synthetic_cover_demo` and visibly says it is virtual practice, not real building information. Long press retains the selected scenario's target. The typed `DiscoveryResult` includes session ID, target, method, input source, camera/heading fallback and `arrivalSimulated=true`. It does not write H02 progress, `introDoneAt`, quiz eligibility or stamps. Completion is emitted once; the Activity sets result extras, requests haptic feedback and scales the character, then leaves the result visible until exit. Pause/recreation invalidates callbacks, cancels pending input and starts a fresh arrival/session.

Prototype defaults: five distinct acceleration excursions (magnitude minus 9.8 >=12 m/s²) within 3 seconds, rearm below 6 and debounce 150 ms; heading enter/exit tolerances 15°/20° around disclosed north 0°; heading freshness 1 second. Cover requires a usable baseline >1 lux and <=20% of that baseline for 1.5 seconds. Light freshness is 2.5 seconds so an ON_CHANGE sensor can provide one dark transition without continuous duplicate samples. Long-press fallback requires 1.5 seconds and cancels on release/cancel/pause. These values are configurable prototypes, not field calibration.
